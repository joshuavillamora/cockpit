# Frontend Guide

How the UI and game-flow code works, explained from Godot basics up to each file. About 1,000 lines of C# plus Godot scenes. The same few patterns repeat, so once you know them the rest is easy to read.

Looking for where a file lives? See [Project Structure](project-structure.md). Looking for what the fighter code must provide? See [Backend Integration](backend-integration.md).

## 1. Godot basics

| Idea | What it means here |
|---|---|
| **Scene (`.tscn`)** | A saved tree of nodes (buttons, labels, sprites). It is the *layout*. |
| **Script (`.cs`)** | C# attached to a node, giving it behavior. The class name must match the filename. |
| **`partial class`** | Godot's generator adds the other half of the class (signals, exported properties). That is why every script says `partial`. |
| **`_Ready()`** | Runs once, when the node and its children are in the scene. Find nodes and connect buttons here. |
| **`_Process(delta)`** | Runs every frame. Used to poll keys on the select screens. |
| **`_UnhandledInput(event)`** | Gets key presses nothing else consumed. `SetInputAsHandled()` stops other nodes reacting too. |
| **`%Name`** in `GetNode<T>("%Name")` | Finds a node marked "Unique Name in Owner", wherever it sits in the scene. |
| **Signal** | An event. `Pressed += Method` runs `Method` when the button is pressed. |
| **Autoload** | A script Godot loads before any scene and keeps alive across scene changes. Listed under `[autoload]` in `project.godot`. |
| **Resource (`.tres`)** | A data file. Used here for chickens, arenas, and the theme. |

### Who writes which file type

| File | Normally made by |
|---|---|
| `.cs` | You, typing code. |
| `.tscn` | The Godot editor (add nodes, set properties in the Inspector, Save). The first versions in this repo were written as text by the AI assistant, but you can open and edit them in the editor like any other scene. |
| `.tres` | The editor (FileSystem dock → New Resource). |
| `.import`, `.uid` | Generated by Godot. Never edit, but do commit. |
| `project.godot` | Project → Project Settings. |

If you rename or delete a node in the editor, the script line that looks it up (`%Name`) must change too.

## 2. Big picture

```
Loading → MainMenu → CharacterSelect → MapSelect → Lobby → game.tscn
                                                            ├─ MatchController (runs rounds)
                                                            ├─ GameHud (bars, big text)
                                                            ├─ PauseMenu
                                                            └─ VictoryOverlay
Always alive: GameManager (state)   SceneFlow (fade + change scene)   SettingsManager   UiFx (cursor, button flash)
```

Each screen reads state from `GameManager`, shows it, and calls `GameManager` or `SceneFlow` when the player moves on. Screens never load each other directly.

## 3. The three autoloads

### `scripts/autoload/GameManager.cs` (shared memory)

```csharp
public static GameManager Instance { get; private set; }
public override void _EnterTree() { Instance = this; }
```
Any script can write `GameManager.Instance`. `_EnterTree` runs before `_Ready`.

```csharp
public CharacterData[] Selected { get; }   // index 0 = P1, 1 = P2
public int[] Wins { get; }                 // rounds won this match (HUD dots)
public int[] MatchWins { get; }            // matches won this session (HUD center score)
```

```csharp
public int Round => Wins[0] + Wins[1] + 1;
public bool IsDeathmatch => Wins[0] == RoundsToWin - 1 && Wins[1] == RoundsToWin - 1;
public int MatchWinner => Wins[0] >= RoundsToWin ? 1 : Wins[1] >= RoundsToWin ? 2 : 0;
```
`=>` makes a computed property, recalculated each time it is read. With `RoundsToWin = 2`, a 1-1 score is the Deathmatch. Draws do not add to `Wins`, so the round number stays and the round is replayed.

```csharp
public bool RegisterRoundResult(int winner) {   // winner: 1, 2, or 0 for a draw
    if (winner > 0) Wins[winner - 1]++;
    bool matchOver = MatchWinner != 0;
    if (matchOver) MatchWins[MatchWinner - 1]++;
    return matchOver;
}
```

What each flow method resets:
- `SelectArena`: new series (map select → lobby), so `MatchWins` and `Wins`. `EnterMatch` goes from the lobby to the match.
- `Rematch`: only `Wins`, so the center score keeps counting.
- `ReturnToMenu`: both.

### `scripts/autoload/SceneFlow.cs` (fade between screens)

```csharp
public async void GoTo(string path) {
    if (busy) return;                 // ignore double presses during a fade
    busy = true;
    await Fade(1f);                   // go black
    GetTree().Paused = false;         // so quitting from pause works
    GetTree().ChangeSceneToFile(path);
    await ToSignal(GetTree(), SceneTree.SignalName.ProcessFrame);  // wait a frame for the new scene
    await Fade(0f);                   // fade back in
    busy = false;
}
```
`async/await` lets code wait for something without freezing the game. `ToSignal` turns a Godot signal into something you can `await`. The fade is a `ColorRect` on a `CanvasLayer` with `Layer = 100` (drawn above everything), animated by a `Tween` on `"color:a"`. `SetPauseMode(Process)` lets the tween run while the game is paused.

### `scripts/autoload/UiFx.cs` (cursor and button flash)
Effects that apply on every screen. `ui_cursor.png` becomes the mouse pointer (scaled up with the window) and is also drawn beside whichever button or slider has keyboard focus. Every button flashes `ui_button_normal_dark.png` for about 0.1 s when pressed, then returns to the light look.

### `scripts/autoload/SettingsManager.cs` (saved options)

- `Load()` reads `user://settings.cfg` with `ConfigFile` (`user://` is a per-user folder outside the project).
- `Apply()` sets bus volumes and the window mode.
- `Mathf.LinearToDb` converts a 0-1 slider to decibels. Values below 0.001 are muted instead of going to minus infinity.
- `_UnhandledInput` toggles fullscreen on **F11**.

## 4. Data as resources

`CharacterData` and `ArenaData` (`scripts/core/`) are `Resource` classes with `[Export]` fields. `[GlobalClass]` makes them show up as creatable types. The `.tres` files in `resources/` fill in the fields (`DisplayName`, `Portrait`, `HudPortrait`, `Scene`, `Playable`).

```csharp
GD.Load<CharacterData>("res://resources/characters/banaba.tres");
```
To add a chicken or a map you add a `.tres`, not new code.

## 5. The screens

### `OverlayScreen.cs` (base class for popups)

```csharp
public static OverlayScreen Open(Node parent, string scenePath, Action onClosed) {
    var overlay = GD.Load<PackedScene>(scenePath).Instantiate<OverlayScreen>();
    overlay.Closed += () => onClosed?.Invoke();
    parent.AddChild(overlay);
    return overlay;
}
```
`Instantiate` makes a copy of the scene, `AddChild` puts it on screen, `Closed` is a signal, and `onClosed` is the callback the opener passes in. `SettingsScreen` and `ControlsScreen` inherit this and get Esc-to-close and `Close()` for free. `SettingsScreen` overrides `OnClosing()` to save settings, and opens Controls on top of itself with the same `Open` call.

### `MainMenu.cs`
`playButton.GrabFocus()` focuses Play so Godot's `ui_up`, `ui_down` and `ui_accept` actions can move and press buttons from the keyboard. Those actions are remapped in `project.godot` to add W, S and Enter. While an overlay is open the menu is hidden, and the `onClosed` callback shows it again.

### `LoadingScreen.cs` (real preloading)

```csharp
ResourceLoader.LoadThreadedRequest(path);                      // start loading in the background
var state = ResourceLoader.LoadThreadedGetStatus(path, info);  // ask how far along it is
```
Each frame `_Process` averages the progress of every path in `Preload`, and moves the bar with `Mathf.MoveToward` so it fills smoothly. It waits at least `MinShowTime`, then swaps the bar for a blinking "PRESS START". The blink is `((int)(blink / 0.5)) % 2 == 0`, which flips every half second. Any key press goes to the menu. **New scenes must be added to the `Preload` list.**

### `CharacterSelect.cs` (the most logic)
State is two small arrays: `cursor[2]` (which chicken each player is on) and `confirmed[2]`.

```csharp
index = (index + direction + count) % count;     // wrap around the list
if (characters[index].Playable) { cursor[player] = index; return; }
```
Adding `count` before `%` stops the index going negative when moving up past 0. The loop keeps stepping until it finds an unlocked chicken, so locked ones are skipped.

`_Process` builds action names per player: `$"p{p+1}_up"` becomes `p1_up` or `p2_up`. Attack confirms, jump cancels. `Refresh()` redraws everything from the state (highlight frames, big preview, "CONFIRM" / "READY!"). Keeping state separate from drawing keeps the code simple.

Enter is `menu_start`, separate from `ui_accept`. Space is `ui_accept` and also P1's jump, so using it would cancel a confirm at the same moment. `BuildColumn` and `BuildPreview` create the TextureRects in code, so the screen grows with the character list.

### `MapSelect.cs`
Same pattern with one shared cursor. Either player moves it, Enter continues to the lobby, and `SelectArena(arenas[cursor])` hands the chosen `ArenaData` to `GameManager`.

### `LobbyController.cs` and `TrainingDummy.cs`
The lobby (`lobby_tutorial.tscn`) sits between map select and the match. Players practice, then both walk into a door to start.

```csharp
fighter.MaxHealth = PracticeHealth;   // 9999, so nobody is knocked out in the lobby
```
`SpawnFighters` works like the match version, but with practice HP and no round logic.

The door is an `Area2D` named `Door`, 64 px wide and touching the right wall, so a fighter cannot run past it. `BodyEntered` and `BodyExited` call `SetInDoor`, which marks that player ready (and fades them) or not ready. When both players are inside, `BeginMatch` locks both fighters, waits 0.8 s, and calls `GameManager.EnterMatch()`. Esc goes back to map select. Rematch skips the lobby and goes straight to the match.

The layout follows the lobby wireframe (frame 12). Each player's panel lists the keys from `ControlsScreen.Rows` as keycaps, so changing a key there updates both screens. The door art switches to its dark version while anyone is inside.

The tips box at the bottom (`ui_tutorial_box`) shows one tip from the `Tips` array, with a dot per tip. It moves on every 4 seconds; `Enter` (`menu_start`) shows the next tip and `Tab` (`lobby_skip_tips`) hides or shows the box. These are handled in `_UnhandledInput`, and nothing in the lobby takes keyboard focus, so player keys like Space never press a button. Add the ability tip once abilities exist.

`TrainingDummy` shows how to make something a fighter can hit. A fighter's attack hitbox calls `TakeDamage` on the parent of any hurtbox (layer 4) it touches, so the dummy only needs a `Hurtbox` `Area2D` child on layer 4 and a public `TakeDamage(int)` method. It counts hits, emits `Hit(hits, damage)` (the lobby shows it on the HITS plate between the panels), and leans back with a spring.

## 6. The match

### `scripts/core/MatchController.cs` (the referee)

```csharp
CallDeferred(MethodName.StartRound);   // wait until the parent finishes setting up
```
Adding children while the parent is still building its children fails, so the call is delayed one step.

Each round:
1. `SpawnFighters` frees old fighters, creates new ones with `data.Scene.Instantiate<Fighters>()`, and sets `PlayerId`, `StartFacingRight` and `InputLocked = true` **before** `AddChild`, so their `_Ready` sees the right values.
2. `hud.Bind(...)` connects the HUD to the new fighters.
3. `await hud.PlayRoundIntro(...)` shows "ROUND N", then "FIGHT!".
4. Fighters unlock and `roundActive = true`.

```csharp
int index = i;
fighter.Died += () => OnFighterDied(index);
```
`index` is a per-iteration copy so each callback remembers its own number.

`OnFighterDied`: the `roundActive` flag stops it running twice. It waits 0.1 s, and if both fighters are dead by then it is a draw. Otherwise the survivor wins. It calls `RegisterRoundResult`, shows the KO text, then shows the victory overlay or starts the next round.

After every `await` there is `if (!IsInstanceValid(this)) return;`. If the player quits mid-round the node is gone and must not be touched.

### `scripts/characters/Fighters.cs` (backend's file; four small hooks added)
- `HealthChanged(int current, int max)` is emitted in `TakeDamage`, so the HUD updates.
- `Died` is emitted in `Die`, which fades and disables the fighter instead of deleting it.
- `InputLocked` makes `_PhysicsProcess` skip input but still apply gravity.
- `StartFacingRight` sets the starting side.

### `GameHud.cs`
`Bind` copies portraits and names in. The key line:

```csharp
fighters[i].HealthChanged += (current, max) => SetHealth(index, current, max, true);
```
"Whenever this fighter's health changes, update bar `index`." `SetHealth` turns health into a 0-100 bar value and tints the bar with `Color(min(1, 2*(1-ratio)), min(1, 2*ratio), 0.2)`: green when full, yellow at half, red near zero. It also tweens the value over 0.15 s.

`ShowText` shows the big center text (ROUND, FIGHT, K.O.): it sets the text, optionally dims the screen, shrinks the text from 1.5x to 1x with `Back` easing for a pop, then waits on a timer created with `processAlways: false` so it pauses with the game.

### `PauseMenu.cs` and `VictoryOverlay.cs`
- `PauseMenu` has `process_mode = Always` in its scene so it works while `GetTree().Paused` is true. It ignores the pause key while the victory screen is up (`MatchWinner != 0`) or an overlay is open.
- `VictoryOverlay.Present(winner)` shows itself, writes "PLAYER N WINS", and focuses Rematch.

## 7. Theme, font and input

- **Theme** (`resources/ui_theme.tres`): default font, 9-slice button and panel textures (the middle stretches, the corners stay crisp), and a `TextButton` variation for plain-text buttons. Applied project-wide via `[gui] theme/custom` in `project.godot`.
- **Input Map**: `p1_*` and `p2_*` gameplay actions, plus `pause`, `menu_start`, and the remapped `ui_*` actions. Scripts check action names, never raw keys, so rebinding happens in one place.

## 8. Patterns to remember

| Pattern | Why |
|---|---|
| State in `GameManager`, screens only display it | Easy to debug; screens stay small. |
| One `GoTo()` for every scene change | Consistent fade, no double clicks. |
| Data in `.tres`, code reads it | Adding content does not change code. |
| `async/await` for timed sequences | Reads top to bottom, no nested callbacks. |
| `IsInstanceValid` after every `await` | Prevents crashes when a scene is left mid-wait. |
| `SetInputAsHandled()` | One key press cannot trigger two things. |
